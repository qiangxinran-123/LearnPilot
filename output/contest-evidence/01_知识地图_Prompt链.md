# 1. 阶段范围与交付边界

## 1.1 本阶段必须实现

本阶段交付以下能力：

### A. 统一知识地图页面

- 取消用户界面中原有的“层级视图 / 关系图”双模式切换。
- 保持课程详情中的“知识结构”本地标签入口。
- 将该标签的主要内容升级为统一知识地图。
- 左侧提供基于真实 CONTAINS 的课程知识导航。
- 中央提供基于真实 PREREQUISITE 的聚焦式关系展示。
- 设置当前选中知识点的统一状态。
- 左侧导航、中央关系图、知识预览同步更新。
- 提供完整知识详情入口。

### B. 聚焦式知识探索

- 默认显示当前知识点及其一层直接前置、后续知识。
- 点击左侧知识点时更换焦点。
- 点击中央其他知识节点时更换焦点。
- 不因节点点击立即离开知识地图。
- 支持连续探索多个相邻知识点。
- 对缺少关系或关系过多的情况提供合理处理。
- 保持所有节点及关系来自真实数据。

### C. 基础布局和导航闭环

- 桌面端采用清晰的导航区、图区与知识预览区。
- 基本适配移动端，不出现严重布局溢出。
- 从知识详情能够返回地图并定位对应节点。
- 地图可以通过明确操作进入知识详情。
- 支持直接访问带有焦点参数的地图 URL。
- 页面刷新、浏览器前进后退及课程切换时状态一致。

# 3. 产品信息架构

## 3.1 页面位置

保留现有：

**Course → 课程详情 → 知识结构**

不新增全局知识图谱导航。

统一展示：

**课程知识地图**

## 3.2 推荐布局

桌面端：

- 顶部：标题、必要说明和搜索状态。
- 左侧：课程知识导航，约占 25%～30%。
- 中央：聚焦式知识依赖关系图。
- 下方或右侧相邻区域：当前知识点快速预览。

根据现有布局可适度调整比例，但必须保证：

- 关系图有足够阅读空间。
- 知识导航可以快速定位节点。
- 当前焦点显著。
- 知识详情入口直接可见。
- 无大量空白和重复内容。

移动端：

- 优先采用单列布局。
- 导航可以折叠或收纳为抽屉。
- 聚焦关系应保持可读。
- 必要时允许使用结构化关联卡片作为小屏替代。
- 不得强行压缩桌面双栏导致文字无法辨认。

不要为了新增布局重做 CourseDetailView 的全部导航体系。

# 4. 左侧课程知识导航

## 4.1 主要职责

左侧负责：

**查找知识点、浏览课程主题、选择地图焦点。**

它不再是一个独立的层级视图产品。

## 4.2 数据来源

使用真实 canonical knowledge nodes。

使用真实 CONTAINS 关系建立父子结构。

不得：

- 使用 KnowledgeCandidate。
- 使用 PREREQUISITE 构建层级树。
- 根据名称或排序推测不存在的父子关系。
- 编造课程章节。
- 将其他课程节点混入当前导航。

## 4.3 基础交互

必须支持：

- 主题展开。
- 主题折叠。
- 按知识点名称搜索。
- 搜索清空。
- 点击节点选中。
- 当前焦点高亮。
- 选中节点在导航中保持可发现。
- 搜索结果可定位并聚焦。
- 展示无搜索结果的状态。

点击知识点后：

1. 更新统一 focusNodeId。
2. 中央关系图切换至对应知识点。
3. 知识快速预览同步切换。
4. 按约定更新 URL 焦点参数。

**不直接进入知识详情页面。**

需要区分：

- 点击展开按钮：只展开或折叠。
- 点击节点名称：切换焦点。

避免点击展开箭头时意外切换节点。

## 4.4 特殊层级

必须正确处理：

- 多个根节点。
- 没有父主题的知识点。
- 孤立知识点。
- 没有任何 CONTAINS 关系的课程。
- 搜索命中深层子节点。
- 主题下知识点较多的情况。

搜索命中深层节点时，应确保该节点能够被发现，不能因为祖先目录折叠而看不到搜索结果。

可以自动展开相关祖先路径，或提供清晰的扁平搜索结果。

必须使用稳定节点 ID，而不是名称作为唯一标识。

# 5. 中央聚焦式知识关系图

## 5.1 核心交互模型

采用：

**Focus Graph — 聚焦式知识关系图**

而不是默认全量 Force-directed Graph。

中央区域围绕当前选中节点，优先展示：

1. 直接前置知识
2. 当前知识点
3. 直接后续知识

推荐语义：

**学习前可以先了解 → 当前知识点 → 接下来还可以看看**

以上只是用户语言；数据仍来自 PREREQUISITE。

## 5.2 关系方向

必须以现有后端的 PREREQUISITE 边定义为准。

若实际约定是 A → B 表示 A 是 B 的先修知识，则：

- B 的前置知识是入边来源。
- A 的后续知识是出边目标。

如果仓库约定相反，应按实际契约转换。

先进行方向验证，再开发 UI。

禁止通过猜测方向或前端排序确定学习依赖。

## 5.3 默认显示范围

默认仅展示：

**当前知识点及其一层直接依赖邻居。**

不得因为两个节点之间存在间接路径，就自动将其视为直接依赖。

对于没有直接先修边的节点：

显示真实空状态或单节点聚焦卡片。

不推断“该知识点无需基础知识”。

对于存在大量直接邻居的节点：

- 保证完整数据仍可访问。
- 初始渲染可限制可见数量。
- 提供“查看更多前置知识”和“查看更多后续知识”之类的真实操作。
- 限制必须稳定且可解释。
- 不得悄悄丢弃超过数量上限的节点。

建议先检查实际数据规模，再选择合适的显示策略。

## 5.4 节点交互

点击中央任意关联节点：

- 将其设为新的焦点。
- 重新计算其直接前置和后续关系。
- 更新左侧选中状态。
- 更新底部知识预览。
- 更新 URL 焦点状态。
- 保持在统一知识地图页面。

**禁止单击节点直接导航到知识详情。**

完整详情只能通过明确的入口进入，例如：

**查看完整知识详情**

该入口必须有实际 Router 导航。

## 5.5 图谱呈现的最低标准

C 阶段需要完成可读且稳定的基础视觉。

要求：

- 当前焦点节点显著。
- 前置和后续知识有明确分区。
- 关系箭头方向正确。
- 长知识点名称合理换行或显示完整信息。
- 不发生严重节点重叠。
- 不出现大量连线交叉导致无法辨认。
- 焦点变化后图能够更新。
- 关系图不溢出容器。
- 低数据量和空数据都能正常显示。

可以复用现有 G6。

如需要重构图的数据适配层，应把它与 Vue 组件解耦。

不必在本阶段追求复杂动画或极致视觉表现。

## 5.6 层级与依赖的视觉分工

**CONTAINS 主要用于左侧知识导航。**

**PREREQUISITE 主要用于中央聚焦图。**

不要默认把所有 CONTAINS 和 PREREQUISITE 同时画在中央，重新制造旧版图谱的混乱。

当前节点所属主题可在知识预览中以简洁文本或标签展示。

# 6. 当前知识快速预览

地图中应提供一个清晰的焦点知识预览区。

至少包含：

- 当前知识点名称。
- 已有的简短描述或解释。
- 真实所属主题（存在时）。
- 明确的“查看完整知识详情”入口。

预览应当轻量。

不得复制知识详情的全部内容。

不显示：

- 大段来源原文。
- 完整关系证据列表。
- 新的 Tutor 输出。
- 虚构的学习建议。
- 掌握度或个性化推荐。

如果 KnowledgeNode 不包含可用描述：

显示合理提示，不调用 LLM 临时生成解释。

“查看完整知识详情”必须使用当前焦点的真实 courseId/nodeId。

# 7. 地图状态与 URL 导航

## 7.1 统一焦点状态

设计一个明确的：

**focusNodeId**

作为地图当前选中知识点的唯一权威状态。

左侧导航、中央关系图和知识预览必须基于同一个状态。

不要让三个组件各自维护不一致的选中节点。

可使用父组件统一状态、Composable 或现有 Store。

以项目当前架构及最小复杂度为准。

## 7.2 URL 同步

建议使用当前课程知识结构页面的 query 参数：

`nodeId=<真实知识点 ID>`

最终参数名以现有路由规范为准。

要求：

- 通过 URL 直接打开指定知识点地图。
- 刷新后正确恢复焦点。
- 切换课程后不保留另一门课程的无效焦点。
- 不存在的 nodeId 安全回退。
- 不显示其他课程的知识点。
- 从知识详情返回时能够定位原知识点。
- 浏览器前进后退能够恢复合理状态。

对于用户连续点击不同知识点：

应设计合理的 push/replace 策略，避免每次点击都制造不必要的浏览器历史条目，同时保证从知识详情返回能恢复正确焦点。

建议：

- 地图内部频繁选中节点，可优先使用 replace。
- 明确的页面导航采用 push。
- 保留必要的返回上下文。

具体以现有 Router 结构为准。

## 7.3 默认焦点规则

如果没有 URL 指定节点：

使用确定性、可解释的默认选择。

例如：

- 首个有效的根主题下知识点。
- 或依照后端稳定排序的首个 canonical node。

必须保证结果稳定。

不得随机选择节点，也不得假装是系统个性化推荐。

如果课程没有知识点：

显示知识模型的真实空状态及既有构建入口。

不要新建一套构建流程。

## 7.4 异步状态

必须防止：

- 课程 A 的慢请求覆盖课程 B。
- 节点 A 的旧预览覆盖节点 B。
- 连续点击时焦点错乱。
- 路由刷新后焦点与图不同步。
- 构建更新后仍显示已删除的旧节点。

优先复用当前知识工作台的请求与缓存管理方式。

# 8. 知识详情与地图的关系

现有知识详情独立路由必须保持不变。

## 8.1 从地图进入详情

通过当前焦点预览中的：

**查看完整知识详情**

进入对应知识详情页。

该页面仍然使用 E.1-A 优化后的：

- 认识这个知识点
- 和哪些知识有关？
- 学习前可以先了解
- 接下来还可以看看
- 知识出处
- 查看依据

不要在 C 阶段改回旧版知识详情样式。

## 8.2 从详情返回地图

在合理位置提供：

**在知识地图中查看**

或者沿用现有返回入口，并支持保持节点上下文。

点击后：

- 进入对应课程的知识结构标签。
- 自动聚焦当前知识点。
- 左侧选中正确。
- 中央显示当前节点关系。
- 预览信息正确。

禁止跳到默认第一个知识点，丢失用户上下文。

## 8.3 不同页面点击行为的区别

必须严格遵守：

| 所在位置 | 点击知识点的行为 |
|---|---|
| 学习概览知识列表 | 直接进入知识详情 |
| 知识地图左侧导航 | 地图内聚焦 |
| 知识地图中央关系图 | 地图内聚焦 |
| 知识地图“查看完整知识详情” | 进入知识详情 |
| 知识详情中的相关知识链接 | 直接进入对应知识详情 |

不要因为复用节点组件而混淆行为。

# 9. 响应式与基本可访问性

## 9.1 桌面端

优先确保常见桌面和笔记本分辨率下：

- 左侧目录不挤压关系图。
- 当前知识点始终突出。
- 关系文字清晰可读。
- 预览和详情按钮可发现。
- 页面可以正常纵向滚动。

## 9.2 移动端
