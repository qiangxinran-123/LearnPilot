# UX-FIX-2 修复与最终验收

状态：COMPLETE。最终验收使用独立的临时 SQLite 数据库、隔离课程和现有测试夹具；未修改用户真实数据，未调用付费 LLM。

## 实现

- 诊断历史和未完成诊断恢复查询使用已有的 INITIAL_DIAGNOSTIC 类型，并保留用户及课程约束；最近诊断仅展示当前课程已提交的正式诊断。学习练习、Evidence 和学习历史没有删除或改写。
- 判断题仅显示“正确 / 错误”，沿用原有答案值与评分。
- 批量确认复用单题发布校验预览待审核题的资格，再逐题调用原审核接口；接口再次验证状态和内容。执行期间禁止重复触发，结束后刷新权威状态，按实际成功响应数和剩余未确认数反馈。结构、关联及来源校验不保证学科内容正确。
- 诊断准备状态使用后端组卷预览的实际可用数、所需题量、覆盖情况和 can_start；待审核时提供审核入口。题库总数是当前题库记录数，不单独统计 AI 生成数，此项为非阻塞限制。

## 最终浏览器验收

- 历史隔离：在临时课程完成正式诊断，最近诊断显示该记录；经 Learn 完成五题练习并结算，反馈显示五条有效学习证据。返回 Diagnose、刷新页面后仍只显示正式诊断；Progress 学习历史同时显示诊断和学习会话。切换到另一个隔离课程时历史为空，切回和刷新后原记录恢复。
- 题量与启动：起初 0 道可用、需要 8 道，10 道待审核题中 9 道通过资格预览、1 道结构异常。批量审核后达到 8 道可用且覆盖 2 个目标，正式诊断实际启动并提供 8 道题；异常题保留待审核。
- 部分失败：仅在隔离浏览器拦截一道审核请求并返回 500，其余请求正常。页面显示“已确认 8 题，2 题未确认”，资格预览显示其中 1 题可重试、1 题需检查；解除拦截后重试成功，刷新后显示 9 道已确认、1 道待审核，与权威数据一致。
- 判断题先前已在隔离浏览器检查中文显示、选择和评分，以及 768、1024、1440 像素布局；本轮完整前端测试包含判断题回归。
